COPILOT UNDERSTANDING:

  THE CORE IDEA:
    A universal, training-free conditioning signal for pixel generators —
    learned entirely without supervision.

  TWO-STAGE PIPELINE:

    Stage 1: Learn the Structure Space (SEG-RDM)
      Real Images
        → SAM (class-agnostic segmentation)
        → I-JEPA ViT-H/14 (encode each region crop)
        → Per-image: { global_vec [256], seg_tokens [N, 256] }
        → RDM trains on this joint distribution

    Stage 2: Condition Any Pixel Generator
      Sample RDM → { global_vec, seg_tokens }
        → Feed as conditioning to StyleGAN2 / DiT / LDM / etc.
        → Generator produces pixels faithful to the structure

  WHY THIS IS STRONG:
    1. Truly Unsupervised: SAM (no labels) + I-JEPA (self-supervised) + RDM
       (no labels) = entirely label-free pipeline
    2. Compositional: { global_vec, seg_1, seg_2, ..., seg_N } is richer than
       a single global embedding — encodes WHERE things are
    3. Generator-agnostic: same RDM conditioning format works for StyleGAN2,
       DiT, LDM via token injection / cross-attention
    4. RDM as structure prior: enables sampling, interpolation, editing,
       structure transfer

  THESIS CLAIM IN ONE SENTENCE:
    "We propose a fully unsupervised compositional conditioning framework:
     a diffusion model over SAM+I-JEPA region embeddings that serves as a
     plug-in structure prior for any pixel generator, enabling structure-guided
     generation, editing, and transfer without any labels."

[4] RESEARCH DISCUSSION: The Alignment Problem
--------------------------------------------------------------------------------

USER: What is this alignment problem? Are you saying the pixel generator will
      not know how the global vector and the seg tokens are related?

COPILOT:

  THE REAL PROBLEM: Does the generator actually use the tokens?

  Failure mode 1 — TOKEN IGNORANCE:
    Generator ignores seg_tokens entirely, uses only global_vec or noise z.
    GAN training doesn't punish this because discriminator only sees real/fake.
    → lambda-seg-align guards against this.

  Failure mode 2 — TOKEN COLLAPSE:
    Generator treats all tokens identically (averages them).
    → lambda-seg-diversity guards against this.

  THE HARD PART (spatial correspondence):
    Nothing in the training explicitly maps token_i → spatial region_i in the
    output. The tokens encode structure from the SOURCE image via SAM+I-JEPA,
    but the generator has no explicit supervision telling it "token 3 should
    appear in the top-left of your output."

  IS THIS FATAL?
    No, because:
    1. I-JEPA features are spatially aware (ViT patch tokens → region crops),
       so tokens implicitly carry spatial information
    2. For generative models the goal is distributional match, not pixel-level
       correspondence

  IMPLICATION FOR EVALUATION:
    The claim should be "structure-guided diversity" not "structure-aligned
    spatial control."

[7] RESEARCH DISCUSSION: RCG Paper Comparison
--------------------------------------------------------------------------------

CONTEXT:
  RCG (Return of Unconditional Generation, Li et al. NeurIPS 2024 Oral) is the
  closest prior work. It uses:
    - MoCo v3 ViT-B/300ep CLS token → single 256-dim vector
    - SimpleMLP RDM (2-layer) to model the CLS distribution
    - Pixel generator (MAGE/DiT/ADM) conditioned on sampled CLS

  SEG-RDM extends RCG by:
    - SAM segmentation → set of N region tokens (not 1 global token)
    - UnifiedSegTransformer operates on [global_vec, seg_1, ..., seg_N]
    - Compositional structure signal (spatial layout encoded in token set)

  KEY DIFFERENCE FROM RCG:
    RCG: 1 token (semantic), no spatial structure
    SEG-RDM: N+1 tokens (semantic + structural layout)

[8] DECISION: Switch from I-JEPA to MoCo v3 for global_vec
--------------------------------------------------------------------------------

PROBLEM: I-JEPA CLS token has eff_rank 11.9/1280 — degenerate low-rank data.
         Root cause: I-JEPA is predictive (masked self-prediction), not
         contrastive. The CLS token accumulates similar representations across
         many images within the same class.

DIAGNOSIS:
  - I-JEPA pre-training pushes SAME image patches to be predictable from
    each other. CLS aggregates these and ends up "averaging" features.
  - MoCo v3 uses instance discrimination (InfoNCE) — EXPLICITLY pushes
    different images apart. Higher CLS diversity expected.

WHY MoCo v3:
  - RCG uses MoCo v3 and explicitly provides download links in its README
  - Known to produce high-quality, diverse CLS embeddings for ImageNet
  - ViT-L checkpoint available; codebase already has loaders in SEG-RDM

USER DECISION:
  → Switch BOTH global CLS AND region tokens to MoCo v3 ViT-L (not ViT-B)
  → Use the trained MoCo contrastive projection head for both (1024 → 256)
  → Write directly to H5 (no NPZ intermediate)

ALIGNMENT LOSS ANALYSIS:
  Q: If both CLS and regions come from MoCo (same embedding space), is the
     alignment loss still valid?
  A: YES. Same embedding space → alignment is MORE meaningful, not less.
     The Transformer self-attention already ensures coherence during denoising.
     Alignment loss is auxiliary (guards against token ignorance), not
     load-bearing.
  NOTE: Can optionally add VICReg-style diversity loss (variance + covariance
     regularization) for global_vec to ensure CLS distribution stays spread.

[14] H5 SCHEMA: MoCo Flat H5 Format

  Output: region_moco_flat.h5

  Dataset          Shape                  Dtype    Description
  ─────────────────────────────────────────────────────────────────────────────
  emb              (N_total_segs, 256)    float32  Region embeddings (MLP head out)

  Lookup: (class_id, name) → row_index
  Built at init in SegmentationMaskDataset using _build_flat_h5_index()
  Same O(1) pattern as original SAM H5 — no separate JSON lookup needed.

[18] METRIC EXPLANATION (Plain Language)
--------------------------------------------------------------------------------

USER: Can you explain these metrics in plain language?

COPILOT EXPLANATION:

  cosine similarity (cos sim):
    How similar two vectors are, ignoring magnitude. Range [-1, +1].
    +1 = identical direction (same "meaning"), 0 = unrelated, -1 = opposite.
    inter-sample cos mean: average similarity between random pairs of images.
      Good embeddings: low (< 0.1) — different images have different features.
      Bad (collapsed): high (> 0.4) — most images look "the same" in feature space.

  effective rank (eff_rank):
    How many dimensions are actually being used by the data.
    Computed from eigenvalue entropy of the covariance matrix.
    eff_rank = 10 out of 256 means only ~10 directions have variance;
    the other 246 are dead / unused.
    Good: high eff_rank (close to full dimensionality).
    Bad: low eff_rank → mode collapse, little diversity.

  eff_rank % (fraction):
    eff_rank / total_dim. Easier to compare across different-sized embeddings.
    Region tokens: 57.9% → rich, diverse distribution.
    I-JEPA CLS:    0.9% → severely collapsed.

  frac > threshold:
    What fraction of random pairs have cosine similarity above the threshold.
    frac > 0.9 = 3.6% means 3.6% of image pairs are nearly identical in
    feature space — that's too many for a "diverse" representation.

  intra-cos mean:
    Average cosine similarity between region tokens WITHIN the same image.
    Moderate is desirable: too low = tokens unrelated (incoherent),
    too high = all regions look the same (no spatial variation).
    Real value 0.318 is reasonable — regions in one image share a theme.

  DINOv2 uses self-distillation with a real CLS token.
  CLS is trained via cross-attention over all patches → strong global summary.
  Known good effective rank for downstream tasks.
  Estimated extraction time: ~17 minutes on 1 GPU for 1.28M images (ViT-L).

NOTE: The excellent region tokens (57.9% eff_rank) come from I-JEPA patch
